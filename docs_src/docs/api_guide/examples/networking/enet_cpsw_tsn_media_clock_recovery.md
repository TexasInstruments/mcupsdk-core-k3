# Ethernet AVB Multistream Media Clock Recovery{#EXAMPLES_ENET_AVB_MULTISTREAM_MCR}

# Introduction
This example demonstrates the Media Clock Recovery feature, which can be used with the Audio Peripheral (McASP) for audio sampling and playback. The main audio clock is generated by the DP83TG721 PHY using its internal PLL. This clock is then provided to the McASP, which derives the bit clock and frame sync clock required by external codec ICs.

See also :\ref ENET_CPSW_AVTP

# Design Overview

To perform Media Clock adjustments, the Media Clock edges must be sampled. Since the typical Media Clock frequency is 48 kHz, sampling every edge is impractical. The standard practice is to sample the Media Clock every 160th edge, resulting in 300 timestamps per second instead of 48,000.

To obtain these 300 Hz timestamps, a dedicated McASP instance is used to derive a 300 Hz signal, called the Timestamping Signal (TSS), from the main audio clock generated by the DP83TG721 PHY. The frequency of these timestamps is aligned with the 48 kHz Media Clock, as both are derived from the same master clock. Therefore, there is a constant time difference between each 300 Hz timestamp and its corresponding 48 kHz Media Clock edge.

This time difference is calculated at startup and is assumed to remain constant during operation. It is compensated for when performing Media Clock adjustments.

To estimate this time difference, both the Media Clock and the Timestamping Signal are routed to the CPTS, where software reads the edge locations and estimates the time difference. After this, the Timestamping Signal is routed to the PHY's GPIO pin, allowing the capture of timestamps with respect to the gPTP clock. These can then be compared against the CRF timestamps sent by the Talker.

# Detailed Design

## One Time Configuration

The following one-time configuration steps must be performed:

### PHY Configuration
- Configure the PHY to generate the codec clock from the PTP PLL.
- Set the CLKOUT pin to output the codec clock.
- At runtime, after estimating the phase difference between the timestamping signal (TSS) and the media clock (MC), connect the TSS to the LED_0 pin and enable event capture on this pin.

### EVM Configuration
- Configure the PHY to generate the codec clock from the PTP PLL on the CLKOUT pin (see the section above).
- Use the external multiplexer to select the PHY on MAC port 1 as the codec clock source.

### SoC Configuration
- Configure the pinmux to connect EXT_REFCLK1 to GPIO1_30.
- Configure and start McASP operations.
- Connect the AFS of both McASPs to ATL BWS signals 0 and 1, respectively.

## Time Difference Estimation
This procedure must be performed every time the link is up, as the clock generated by the PHY is restarted whenever the link goes down and up.
- Connect ATL BWS0 (carrying TSS) to CPTS hardware push event 0, and collect 4 timestamps captured by CPTS.
- Connect ATL BWS1 (carrying MC) to CPTS hardware push event 1, and collect 4 timestamps captured by CPTS.
- Disconnect ATL BWS1 from CPTS hardware push event 1. This is important; otherwise, CPTS will generate 48,000 interrupts per second, which may starve RTOS tasks.
- Estimate the phase difference between MC and TSS using the collected timestamps.
- Connect ATL BWS0 to SYNC1_OUT, which will be timestamped by the PHY using its internal gPTP clock.

# Steps to Run the Example

## Build the example

- When using CCS projects to build, import the CCS project for the required combination
  and build it using the CCS project menu (see \ref CCS_PROJECTS_PAGE).
- When using makefiles to build, note the required combination and build using
  make command (see \ref MAKEFILE_BUILD_PAGE)

## Run the example
\attention If you need to reload and run again, a CPU power-cycle is MUST

- Load CRF Talker and CRF Listener Applications on the EVMs and start the Applicaiton within a couple of seconds.
- Wait for 30 seconds and observe the line `INF:avtp:Lock = 1, SlipCounter = 0, Course Correction = 0, Fine Correction = 4` on the CRF Listener Logs.
- The `Lock = 1` indicates that the Media Clock is synchronized.

# Troubleshooting
- The link is unstable (i.e., both EVMs' Ethernet links repeatedly go up and down). Check the automotive Ethernet cable and re-run the application. You may also try increasing the EnetPHY tick period from 100 ms to 1 s.
- Assertion failure: `crfHwConfig_getEdgeDiff:321: goodTopSample != 0 failed !!!`. Ensure that pins 2 and 3 on J29 are bridged. If the issue persists, try disconnecting any probes connected to the timestamping signal and media clock signal, then try again.
- McASP open failure: Verify that the PHY is linked up. Also, check for the presence of the 24.576 MHz clock generated by the PHY at TP10 (on the PHY add-on card).
