# SBL Booting Linux From eMMC
## Introduction

:::{only} SOC_AM64X
   - SBL booting Linux from eMMC (see `EXAMPLES_DRIVERS_SBL_EMMC_LINUX`) is a secondary bootloader application that boots Linux on A53 core and RTOS/NORTOS application on R5, M4 cores.
   - The bootloader makes use of two appimages
       - One containing the application images(RTOS/NORTOS) for R5, M4 cores.
       - Other containing the Linux binaries(ATF, OPTEE, SPL) for A53 core.
:::


:::{only} SOC_AM62X
   - SBL booting Linux from eMMC (see [EXAMPLES_DRIVERS_SBL_EMMC_LINUX_MULTISTAGE](../examples/drivers/sbl_emmc_linux_multistage.md)) is a secondary bootloader application that boots Linux on A53 core and RTOS/NORTOS application on R5, M4 cores.
   - The bootloader makes use of 6 appimages
       - A Linux appimage containing the **Linux binaries (ATF, OPTEE, A53 SPL)**.
       - tiboot3.bin with **SBL stage1, TIFS, BoardConfig**
       - Appimage for **SBL stage2**
       - Appimage for **MCU M4**
       - Appimage for **HSM M4**
       - DM firmware appimage for **DM R5**
   - Boots R5F, MCU-M4, HSM-M4 cores and Linux on A53 from eMMC.
   - SBL booting Linux can be used when early booting of R5F, HSM-M4 and MCU-M4 cores are required. When using uBoot, the application will start running on R5F, HSM-M4 and MCU-M4 cores only after booting Linux
:::


:::{only} SOC_AM62AX
   - SBL booting Linux from eMMC (see [EXAMPLES_DRIVERS_SBL_EMMC_LINUX_MULTISTAGE](../examples/drivers/sbl_emmc_linux_multistage.md)) is a secondary bootloader application that boots Linux on A53 core and RTOS/NORTOS application on R5, C7x, M4 cores.
   - The bootloader makes use of 7 appimages
       - A Linux appimage containing the **Linux binaries (ATF, OPTEE, A53 SPL)**.
       - tiboot3.bin with **SBL stage1, TIFS, BoardConfig**
       - Appimage for **SBL stage2**
       - Appimage for **MCU R5**
       - Appimage for **HSM M4**
       - Appimage for **C75**
       - DM firmware appimage for **DM R5**
   - Boots R5F, MCU-R5, HSM-M4, C75 cores and Linux on A53 from eMMC.
   - SBL booting Linux can be used when early booting of R5F, HSM-M4, C75 and MCU-R5 cores are required. When using uBoot, the application will start running on R5F, HSM-M4, C75 and MCU-R5 cores only after booting Linux
:::


:::{only} SOC_AM62PX
   - SBL booting Linux from eMMC (see [EXAMPLES_DRIVERS_SBL_EMMC_LINUX_MULTISTAGE](../examples/drivers/sbl_emmc_linux_multistage.md)) is a secondary bootloader application that boots Linux on A53 core and RTOS/NORTOS application on R5, M4 cores.
   - The bootloader makes use of 5 appimages
       - A Linux appimage containing the **Linux binaries (ATF, OPTEE, A53 SPL)**.
       - tiboot3.bin with **SBL stage1, TIFS, BoardConfig**
       - Appimage for **WKUP R5 with SBL stage2**
       - Appimage for **MCU R5**
       - Appimage for **HSM M4**
   - Boots WKUP-R5F, MCU-R5, HSM-M4 cores and Linux on A53 from eMMC.
   - SBL booting Linux can be used when early booting of WKUP-R5F, HSM-M4 and MCU-R5 cores are required. When using uBoot, the application will start running on WKUP-R5F, HSM-M4 and MCU-R5 cores only after booting Linux.
:::

- The Linux appimage can be generated by using [Linux Appimage Generator Tool](../components/tools/tools_boot.md)
- The appimages will be flashed to the offset on eMMC specified by SysCfg, the SBL parses the appimages from these locations, loads and run the cores.

## Bootflow for SBL booting linux from eMMC


:::{only} SOC_AM62AX
   :::{admonition} Note
   The binaries for R5F, M4F, C75 cores need not be in the linux root partition `(root/lib/firmware)`, when SBL is booting Linux. :::
   :::


:::{only} SOC_AM62PX
   :::{admonition} Note
   The binaries for WKUP-R5F, MCU-R5 cores need not be in the linux root partition `(root/lib/firmware)`, when SBL is booting Linux. :::
   :::


:::{only} SOC_AM62X
   :::{admonition} Note
   The binaries for R5F, M4F cores need not be in the linux root partition `(root/lib/firmware)`, when SBL is booting Linux. :::

:::{only} SOC_AM62PX
   - The bootflow for SBL booting Linux is as follows


       ![Bootflow for SBL booting Linux](../images/bootflow/sbl_booting_linux_emmc_am62px.png)
   - The stage 2 bootloader and the Device manager application are combined as a single appimage
   - The SBL stage 1 will self load SBL stage 2 + Device manager application to WKUP-R5 core and run self CPU
   - Then two threads namely, main thread and SBL stage 2 thread will be created for parallel execution
   - The main thread will open the drivers required for application, do the SciServer init and run the WKUP-R5 core application
   - The SBL thread will set the clock and open the drivers for the peripherals used by the SBL.
   - Then it boots the HSM-M4 core, MCU-R5 core and linux on A53 core.

   :::{admonition} Note
   - The peripherals used by SBL and application are separated by using the sysconfig option 'Instance added by bootloader'.
   :::

   :::{admonition} Note
   - For the peripherals used by SBL, the 'Instance added by bootloader' option is enabled in the sysconfig as shown.
   :::



   :::{admonition} Note
   ![Instance added by bootloader - sysconfig option](../images/bootflow/sysconfig_option_addedbybootloader.png)
   :::


   :::{admonition} Note
   - These peripherals will be opened/closed in the SBL thread and it will not get opened/closed in the common Drivers_open/Drivers_close function called in the main thread.
   :::


:::


## EMMC Partitioning


:::{only} SOC_AM64X
   :::{admonition} Note
   The default SD card image for AM64x-evm can be used to boot Linux using SBL
   :::

   :::{admonition} Note
   The tiboot3.bin, tispl.bin will not be used for booting Linux when using SBL booting Linux.
   :::

   :::{admonition} Note
   The R5 binaries in the root partition (eg : `root/lib/firmware/am64-main-r5f0_0-fw`) will not be used when SBL boots Linux and R5,M4 cores. :::
   :::


:::{only} SOC_AM62X
   :::{admonition} Note
   The default SD card image for AM62x-evm can be used to boot Linux using SBL
   :::

   :::{admonition} Note
   The tiboot3.bin, tispl.bin will not be used for booting Linux when using SBL booting Linux.
   :::

   :::{admonition} Note
   The M4 binary in the root partition (eg : `root/lib/firmware/am62-mcu-m4f0_0-fw`) will not be used when SBL boots Linux and M4 cores. :::
   :::


:::{only} SOC_AM62AX
   :::{admonition} Note
   The default SD card image for AM62Ax-evm can be used to boot Linux using SBL
   :::

   :::{admonition} Note
   The tiboot3.bin, tispl.bin will not be used for booting Linux when using SBL booting Linux.
   :::

   :::{admonition} Note
   The R5 binaries in the root partition (eg : `root/lib/firmware/am62a-mcu-r5f0_0-fw`) will not be used when SBL boots Linux and MCU-R5,C75 cores. :::
   :::


:::{only} SOC_AM62PX
   :::{admonition} Note
   The default SD card image for AM62Px-evm can be used to boot Linux using SBL
   :::

   :::{admonition} Note
   The tiboot3.bin, tispl.bin will not be used for booting Linux when using SBL booting Linux.
   :::

   :::{admonition} Note
   The R5 binaries in the root partition (eg : `root/lib/firmware/am62p-mcu-r5f0_0-fw`) will not be used when SBL boots Linux and MCU-R5 core. :::
   :::


- eMMC uses two patitions to boot Linux
    - A boot patition
        - tiboot3.bin
        - tispl.bin
        - u-boot.img
        - uboot.env
    - A ext4 partition in the user data area containing
        - Linux Kernel image
        - Linux DTB
        - Linux file system
